# Инструкция по деплою на Render (на русском)

Это руководство объясняет, как развернуть проект Mathbot на Render.com.

## Структура проекта

Проект состоит из двух сервисов:
1. **Bot/API сервис**: Python сервис с Telegram ботом и FastAPI бэкендом
2. **Web сервис**: Next.js фронтенд приложение

## Необходимые условия

- Аккаунт на Render.com (бесплатный тариф подходит)
- GitHub репозиторий с этим кодом
- Токен Telegram бота (от [@BotFather](https://t.me/botfather))

## Шаги для деплоя

### Вариант 1: Использование render.yaml (Рекомендуется)

1. **Загрузите репозиторий на GitHub**
   - Сделайте fork этого репозитория или загрузите свой код

2. **Перейдите в панель управления Render** (https://dashboard.render.com/)

3. **Создайте новый Blueprint Instance**
   - Нажмите "New" → "Blueprint"
   - Подключите ваш GitHub репозиторий
   - Render автоматически обнаружит файл `render.yaml`
   - Нажмите "Apply"

4. **Настройте переменные окружения**
   
   Для сервиса **mathbot-api** добавьте:
   ```
   BOT_TOKEN=ваш_токен_telegram_бота
   ```

   Для сервиса **mathbot-web** добавьте:
   ```
   NEXT_PUBLIC_API_URL=https://mathbot-api.onrender.com
   NEXTAUTH_URL=https://mathbot-web.onrender.com
   NEXTAUTH_SECRET=<сгенерируйте командой: openssl rand -base64 32>
   ```

   Опционально (для Google OAuth):
   ```
   GOOGLE_CLIENT_ID=ваш_google_client_id
   GOOGLE_CLIENT_SECRET=ваш_google_client_secret
   ```

5. **Разверните**
   - Render автоматически соберет и развернет оба сервиса
   - API сервис будет доступен по адресу: `https://mathbot-api.onrender.com`
   - Web сервис будет доступен по адресу: `https://mathbot-web.onrender.com`

### Вариант 2: Ручной деплой

#### Развертывание Bot/API сервиса

1. **Создайте новый Web Service**
   - Перейдите в панель управления Render
   - Нажмите "New" → "Web Service"
   - Подключите ваш GitHub репозиторий
   - Настройте:
     - **Name**: mathbot-api
     - **Environment**: Python 3
     - **Region**: Frankfurt (или ближайший к вам)
     - **Branch**: main
     - **Root Directory**: bot
     - **Build Command**: `pip install -r requirements.txt`
     - **Start Command**: `python main.py`
     - **Plan**: Free

2. **Добавьте переменные окружения**:
   ```
   BOT_TOKEN=ваш_токен_telegram_бота
   PYTHON_VERSION=3.11.0
   ```

#### Развертывание Web сервиса

1. **Создайте новый Web Service**
   - Нажмите "New" → "Web Service"
   - Подключите ваш GitHub репозиторий
   - Настройте:
     - **Name**: mathbot-web
     - **Environment**: Node
     - **Region**: Frankfurt
     - **Branch**: main
     - **Root Directory**: web
     - **Build Command**: `npm install && npm run build`
     - **Start Command**: `npm start`
     - **Plan**: Free

2. **Добавьте переменные окружения**:
   ```
   NEXT_PUBLIC_API_URL=https://mathbot-api.onrender.com
   NEXTAUTH_URL=https://mathbot-web.onrender.com
   NEXTAUTH_SECRET=<ваш-секрет>
   NODE_VERSION=18.17.0
   ```

## ⚠️ ВАЖНО: Почему задачи пропадают при обновлении?

### Проблема

При каждом деплое (обновлении кода в main ветке) на Render **все данные сбрасываются**:
- База данных SQLite (`database.db`) — **удаляется**
- Изображения задач (`bot/images/`, `bot/solutions/`) — **удаляются**

Это происходит потому, что Render использует **эфемерное (временное) хранилище** на бесплатном тарифе. При каждом деплое создается новый контейнер с чистой файловой системой.

### Решения проблемы

#### Вариант 1: Render Disk (Рекомендуется для простоты)

Render Disk — это постоянное хранилище, которое сохраняется между деплоями.

1. **Перейдите в настройки сервиса mathbot-api** в панели управления Render
2. **Добавьте Disk**:
   - Нажмите "Add Disk"
   - **Name**: mathbot-data
   - **Mount Path**: `/data`
   - **Size**: 1 GB (достаточно для начала)
3. **Добавьте переменную окружения**:
   ```
   DATABASE_PATH=/data/database.db
   IMAGES_PATH=/data/images
   SOLUTIONS_PATH=/data/solutions
   ```

**Примечание**: Render Disk доступен только на платных тарифах (от $7/месяц).

#### Вариант 2: Внешняя база данных PostgreSQL

1. **Создайте PostgreSQL на Render**:
   - Нажмите "New" → "PostgreSQL"
   - Выберите бесплатный тариф (90 дней) или платный
2. **Получите DATABASE_URL** из настроек базы данных
3. **Добавьте переменную окружения** в mathbot-api:
   ```
   DATABASE_URL=postgres://user:password@host:port/database
   ```

**Примечание**: Потребуется модификация кода для поддержки PostgreSQL.

#### Вариант 3: Использование другого хостинга

Рассмотрите хостинги с постоянным хранилищем:
- **Railway.app** — имеет постоянное хранилище
- **Fly.io** — поддерживает постоянные тома
- **DigitalOcean App Platform** — с managed databases
- **Собственный VPS** (DigitalOcean, Hetzner, и т.д.)

#### Вариант 4: Резервное копирование перед деплоем

Если вы продолжаете использовать бесплатный тариф Render:

1. **Перед каждым деплоем** экспортируйте данные:
   - В Telegram боте: `/export` — экспорт пользователей
   - Скачайте изображения вручную через SSH/SFTP
   
2. **После деплоя** импортируйте данные обратно

**Это временное решение и не рекомендуется для продакшена!**

### Рекомендация

Для стабильной работы бота с сохранением данных:

| Компонент | Бесплатное решение | Платное решение |

## Важные замечания

### Ограничения бесплатного тарифа
- Сервисы на бесплатном тарифе останавливаются после 15 минут неактивности
- Первый запрос после остановки может занять 30-60 секунд для "пробуждения"
- Бесплатный тариф включает 750 часов/месяц на каждый сервис
- **Данные не сохраняются между деплоями!**

### Сохранение базы данных
- База данных SQLite (`database.db`) хранится на эфемерном диске
- **⚠️ При каждом деплое база данных сбрасывается!**
- Для продакшена **обязательно** используйте внешний сервис базы данных

### Хранение изображений
- Изображения хранятся в директориях `bot/images/` и `bot/solutions/`
- **⚠️ При каждом деплое изображения удаляются!**
- Для продакшена **обязательно** используйте облачное хранилище (S3, Cloudinary и т.д.)

### Свой домен
- Вы можете добавить свой домен в панели управления Render
- Не забудьте обновить `NEXTAUTH_URL` и `NEXT_PUBLIC_API_URL` соответственно

## Решение проблем

### Bot API не отвечает
- Проверьте, что `BOT_TOKEN` установлен правильно
- Проверьте логи в панели управления Render
- Убедитесь, что сервис запущен (не спит)

### Web не может подключиться к API
- Проверьте, что `NEXT_PUBLIC_API_URL` указывает на правильный URL API сервиса
- Проверьте настройки CORS если необходимо
- Убедитесь, что оба сервиса запущены

### Ошибки базы данных
- Проверьте, что база данных инициализирована правильно
- Проверьте логи на SQL ошибки
- Убедитесь, что `database.db` имеет правильные права доступа

## Рекомендации для продакшена

Для продакшен деплоя рекомендуется:

1. **Обновиться с бесплатного тарифа** для:
   - Отсутствия остановки при неактивности
   - Больше ресурсов
   - Лучшей производительности

2. **Использовать внешнюю базу данных**:
   - PostgreSQL на Render
   - Или другой управляемый сервис базы данных

3. **Использовать облачное хранилище**:
   - AWS S3
   - Cloudinary
   - Google Cloud Storage

4. **Настроить мониторинг**:
   - Отслеживание ошибок (Sentry)
   - Мониторинг времени работы
   - Мониторинг производительности

5. **Настроить правильное управление секретами**
   - Никогда не коммитьте секреты в Git
   - Используйте переменные окружения Render
   - Регулярно обновляйте секреты
